# SDK Conversations

`createConversationsController` shares one typed state across the original workspace panel and front contribution. The host supplies a native `AccessController`, the declared T06 operation client, an audience and a context. Themes receive rendered children, not the controller.

The controller keeps immutable snapshots for `useSyncExternalStore`. The conversation and message lists are bounded pages with a cursor; an empty filtered page can still have a continuation. Drafts are kept in memory and scoped session storage while edited, then saved through the declared `draft.save` operation. The selected draft is editable only after `draft.read` confirms its current revision. A delayed or failed read leaves the local text intact and blocks `draft.save` and `turn.start` until a fresh read succeeds. Logout or identity changes purge the previous scope. A temporary access failure suspends reads without attributing old data to another identity.

Commands persist their request key before invoking the operation. An unknown outcome stays unknown. `reconcileUnknown()` reads the operation status by that key without sending the command again. In the absence of a provider the detail explicitly returns `no_provider`; no assistant response is generated by the controller.

T15 adds `startTurn(conversationId, body, modelId)` as the sole user-message send mutation. The command uses the selected conversation and draft revisions and records a request key. Confirmed sends append the returned message without resetting loaded history; terminal refreshes merge recent messages by identity and revision. A lost response is reconciled by the same key; the SDK never starts a second turn automatically. `driveTurn(conversationId, turnId)` calls the host's same-origin, native-session route and then passively rereads `turn.read` and `event.list`; it never handles an OpenAI credential or provider response ID. The selected turn ID is kept in scoped session storage so a mounted/reloaded panel can inspect and resume it. Client deactivation aborts its pending HTTP read, which does not imply cancellation of the provider. `cancelTurn` sends a separate explicit mutation using the turn's current revision.
