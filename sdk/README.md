# @creezio/sdk 1.10.0

This package is the public authoring surface for Creezio modules. This source tree declares SDK 1.10.0; a version in source does not by itself establish archive publication. Official archive availability, source revision and integrity are recorded in [GitHub Releases](https://github.com/creezio/Creezio-D1R2/releases). Earlier published SDK archives remain available with their own source revision and integrity evidence. Published archives remain immutable; consumers retain their verified archive until an explicit update.

SDK 1.8 adds an atomic file-link snapshot port for declared operations, read-only analytics collection flags and the Resend signed-webhook scheme. File-link snapshots remain private and commit with the business change and delivery intent; the port exposes neither SQL nor a credential. Collection flags come from the installation authority under current access and storage guards, including when business data uses an isolated database. They do not grant an analytics read or enable collection automatically. The delivery transport also exposes an explicit update retry; the operator determines eligibility after verifying the preserved artifact, schema receipt and remote versions.

SDK 1.7 adds a read-only workspace navigation catalogue port. The host supplies compiled contributions under the current identity and projection; modules store cosmetic overrides rather than destinations or permissions. This port does not grant access to a view or change workspace routing.

SDK 1.6 adds `OperationContext.operations?.query({moduleId, operationId, input})` for declared public reads and `OperationContext.diagnostics` for native analytics. An intermodule read requires a versioned public contract, a dependency and an `effects.calls` reference. The host retains identity, audience, context, cancellation and budgets. Nested commands are refused.

SDK 1.6 also declares bounded connector mutations, signed provider webhooks, provider search projections and durable connector deliveries. A mutation uses a fixed resource descriptor and the host credential; the handler never receives an arbitrary HTTP client or decrypted secret. A delivery declaration in `contracts.deliveries` binds an `on-invoke` command to a same-module prepare query, a public provider readiness contract, one connector resource and a module-owned receipt projector. The host records the intent before an outbound call, settles accepted or rejected receipts under current guards, and leaves uncertain outcomes for status inspection without repeating the provider call. These contracts do not add a scheduler or establish live provider qualification. See [the module standard](../docs/STANDARD-MODULE.md) and [the contract schemas](contracts/schemas/v1/README.md).

SDK 1.9.0 adds `OperationFilesPort.stageRemote` and `prepareBatchPublication`. A connector's compiled `binaryDownloads` policy fixes the API metadata path and CDN origin/path. The host downloads one signed-event-backed attachment per stage command, checks the active connection and vault before each hop and at commit, then keeps the bytes in private R2. A later import publishes an exact set of up to 50 staged references in one D1 batch with the business record. These contracts are in the published SDK 1.9.0 archive. See [files/README.md](files/README.md).

SDK 1.9 also adds optional `DeliveryTransport.rejectUpdate` for an explicitly verified Cloudflare validation rejection. Older adapters remain compatible: the action is hidden and a direct call fails closed when this capability is absent. A known Cloudflare 10021 validation rejection is not eligible for retry. Confirming rejection preserves the applied D1 schema, data and artifact; it neither uploads code nor rolls back data.

SDK 1.9.0 exports the pure Delivery controllers and view models through `delivery/controller`, `delivery/view-model`, `delivery/update-controller`, `delivery/update-view-model` and `delivery/types`. Delivery modules use these package subpaths so their runtime and validation archives do not depend on repository source paths.

SDK 1.9.1 updates composition validation: different module IDs cannot share one npm package source, and disabled modules do not participate in effective dependency ordering. The already published 1.9.0 archive remains immutable.

SDK 1.10.0 adds retired permission history to the composition lock schema. A removed module or permission keeps its module ID, origin and retired permission IDs as inactive references; they cannot authorize an operation or a new grant. The existing Node-only `@creezio/sdk/contracts/node` validator accepts this lock shape. The Core reconciliation helper is internal and no new author-facing export is added. This source version is a candidate until its exact archive is qualified and published.

Earlier versions introduced the private widget image contract and `widgetCalls` binding (1.5), fixed canonical JSON command field validation (1.4.1), extended fixed GET connector resources (1.4), added linked file reads (1.3), and introduced the connector type and command journal subpaths (1.2). See [files/README.md](files/README.md) and [operations/README.md](operations/README.md). Modules import only declared package subpaths and declare the SDK version they require.

To build a local 1.10.0 candidate with Node 24, use the repository's existing dependencies and `sdk/dist`, then run `npm run sdk:build` and `npm pack --workspace sdk --ignore-scripts --json --pack-destination <existing-artifact-directory>` from the repository root. The `creezio-sdk-1.10.0.tgz` archive contains ESM JavaScript, declarations and versioned schemas. It excludes the root application, databases, secrets and Worker. The `@creezio/sdk/contracts/node` entry is Node-only; handlers and browser views must not import it. React and React DOM are shared peer dependencies.

Before any publication, qualify a clean `main` commit with CI and the consuming module archives. Record the exact commit and tree, package inventory, file hashes, tarball SHA-256 and byte count. Check every exported JavaScript and declaration path in the packed archive. Tag that exact commit and verify the uploaded release asset after download. A source checkout, local package, draft release or tag alone does not establish public availability; no npm registry publication is implied.
