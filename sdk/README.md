# @creezio/sdk 1.2.0 — source candidate

This package is the module authoring surface for Creezio. Version 1.2.0 adds the public command journal described below. The delivery subpaths introduced in 1.1.0 remain available. The root application remains private; a module imports only explicit subpaths in `package.json.exports`. Published `sdk-v1.0.0` and `sdk-v1.1.0` archives remain immutable. Version 1.2.0 is a source candidate, not a public release.

The 1.2.0 candidate also exposes `@creezio/sdk/connectors/types` and the optional `contracts.connectors` manifest section. Modules declare closed GET resources and private configuration/vault models; the host injects an operation-scoped `ConnectorPort` without disclosing its credential. Key configuration uses the limited `ProviderSecretsPort` type exported by `operations/handler`. This does not provide unrestricted network access, a bundled provider application, or remote mutation support. See [the module standard](../docs/STANDARD-MODULE.md) and [n8n implementation](../docs/IMPLEMENTATION-T26.md).

Build the package from a clean, CI-qualified `main` commit with Node 24. Verify the exact commit and tree, reuse `sdk/dist` after removing only obsolete generated outputs that are no longer in use, then run `npm run sdk:build` and `npm pack --workspace sdk --ignore-scripts --json --pack-destination <existing-artifact-directory>` from the repository root. The resulting `creezio-sdk-1.2.0.tgz` contains ESM JavaScript, TypeScript declarations and the versioned contract schemas. It does not include the application, its databases, secrets or a separate Worker.

Handlers import `OperationError` and the plan-only context from `@creezio/sdk/operations/handler`. The host imports the same runtime error from `@creezio/sdk/operations/error`; a separately bundled copy would break `instanceof`. React and React DOM are shared peer dependencies for views. `@creezio/sdk/contracts/node` is a Node-only validation entry and must not be imported by a Worker handler or browser view.

The source candidate also defines `@creezio/sdk/operations/command-journal` for native browser views. It records only bounded command metadata before a mutation, blocks replay while the outcome is uncertain, and inspects the existing `OperationClient.status` path. Its implementation and declarations have no private core import. See [operations/README.md](operations/README.md) for the API and persistence contract. This entry is not in the previously published SDK archives; a separate version, build and release qualification are still required.

Before publication, record the main commit/tree, pack inventory, SHA-256 of every file, tarball digest and byte count, and successful CI run on that same main commit. Check every exported JavaScript and declaration path, including command journal and delivery, against the packed archive. Create an annotated `sdk-v1.2.0` tag on that exact commit and a draft GitHub Release; upload `creezio-sdk-1.2.0.tgz`, download and verify it, then publish and verify the public asset again. A draft, tag or local tarball alone is not a public release. No npm registry publication is implied. Existing consumers retain their verified SDK archive until an explicit update qualifies the new package.
