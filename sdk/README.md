# @creezio/sdk 1.1.0 — paquet prêt pour la release

This package is the module authoring surface for Creezio. Version 1.1.0 adds the public `@creezio/sdk/delivery/context` and `@creezio/sdk/delivery/transport` subpaths used by the optional T32 delivery module and its host. The root application remains private; a module imports only the explicit subpaths in `package.json.exports`. The public T30 `sdk-v1.0.0` archive and its digest remain immutable. Version 1.1.0 is ready to qualify for a separate release; it is not public until its GitHub Release asset is uploaded, verified and published.

Build the package from a clean, CI-qualified `main` commit with Node 24. Verify the exact commit and tree, prepare a clean `sdk/dist` output, then run `npm run sdk:build` and `npm pack --workspace sdk --ignore-scripts --json --pack-destination <existing-artifact-directory>` from the repository root. The resulting `creezio-sdk-1.1.0.tgz` contains ESM JavaScript, TypeScript declarations and the versioned contract schemas. It does not include the application, its databases, secrets or a separate Worker.

Handlers import `OperationError` and the plan-only context from `@creezio/sdk/operations/handler`. The host imports the same runtime error from `@creezio/sdk/operations/error`; a separately bundled copy would break `instanceof`. React and React DOM are shared peer dependencies for views. `@creezio/sdk/contracts/node` is a Node-only validation entry and must not be imported by a Worker handler or browser view.

Before publication, record the main commit/tree, the pack inventory and SHA-256 of every file, the tarball SHA-256 and byte count, and the successful CI run on that same main commit. Check every exported JavaScript and declaration path, including both delivery subpaths, against the packed archive. Create an annotated `sdk-v1.1.0` tag pointing to that exact commit; create a draft GitHub Release for the tag, upload `creezio-sdk-1.1.0.tgz`, download it to verify its bytes and digest, then publish and verify the asset again. A draft, tag or local tarball alone is not a public release. No npm registry publication is implied. The starter release continues to use its exact verified 1.0.0 tarball until it adopts a separately verified SDK archive.
