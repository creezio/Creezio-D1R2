# Workspace SDK

`Workspace` receives the host-owned `AccessController`, a fresh authorization projection, compiled `RuntimeView[]` and `RuntimeNavigation[]`, the operations client, and a fixed `contextId`. The host supplies `homeViewId` for a pinned landing tab, `initialUrl` for a direct link, and `onLocationChange` to mirror the active panel URL. Modules render directly as React components inside stable panels. No SDK file imports private Next or Vinext contexts.

Panel identity uses the declared view ID and `panel.identityFields`. The generated `validateInput` checks a view's route and query input before opening it. Navigation, order, locks, local history and retained subviews are per panel. Inactive panels remain mounted for `retention: preserve`, receive `active=false`, become inert and cannot use the guarded operations client. Views should stop their own timers and effects when `active` or `useWorkspaceActivity()` is false.

Module overlays must use `WorkspacePortal`. Its DOM stays inside the panel's hidden/inert boundary, including for an inactive retained subview. Portals mounted directly in `document.body` do not inherit that boundary and are outside this SDK contract.

During session or projection verification, private panels are masked and operations are suspended while their React state remains mounted. Confirmed logout/anonymity, a different identity/context/composition, or a projection that removes a view purges the affected panels. An unknown operation outcome is not retried automatically. Views use the operation client's explicit status read where available.

The browser adapter restores tabs, routes, histories and explicitly declared panel state from sessionStorage only after a fresh matching projection. Records are scoped to the session, principal, audience, context and composition. `panel.stateSchema` optionally references a module schema; the generated `validateState` checks `panelState.data` when saved and restored. Views opt in through `navigation.readPanelState()` / `savePanelState()`, bound to their own `panelId`. No form or credential is captured automatically. Inactive panels may read their own already-authorized state to mount a restored view, but cannot write it or invoke navigation/mutations. Mechanical subview and scroll state is bounded separately. Confirmed access refusal purges the scope; transient network failures suspend it. Normal unmount preserves the snapshot. Browser, Worker and hosted behavior require separate qualification.

`savePanelState` returns true only when the validated state is persisted. A false return can leave it available in memory while browser storage is unavailable or full; views must not promise restoration after reload in that case. Persistence is bounded to 128 KiB UTF-8 for the workspace and 8 KiB of declared data per panel. An unsuccessful write preserves the previous valid snapshot.

The SDK exposes stable panels and navigation independently of presentation. The host's `admin/workspace` adapts the original Creezio tab bar, sidebar, page chrome, search trigger and theme. Its `renderShell` callback does not grant permissions. Modules can publish actions through `useRegisterPageToolbar` in the public `sdk/workspace/toolbar` API, scoped to their `panelId` and location; they do not import private admin components. `useRegisterWorkspaceMetadata` in `sdk/workspace/metadata` supplies panel titles, subtitles, kind and internal breadcrumbs. The shell consumes the aggregate metadata snapshot for all tabs; these presentation values are not persisted or used for authorization.
