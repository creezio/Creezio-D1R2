# Pages et navigation natives

`creezio.pages-navigation` conserve dans D1 les pages, sections, réglages, métadonnées SEO et liens de navigation. L'éditeur du workspace utilise les opérations canoniques `page.*`, `navigation.*` et `media.*`. Un brouillon est distinct de son snapshot publié. `page.reset` et `navigation.reset` ne modifient que le brouillon et exigent une révision fraîche. Les médias sont des fichiers R2 privés liés à une page ; détacher un fichier ne détruit pas ses octets.

La vue front authentifiée lit uniquement `page.published.*` et `navigation.published`. Le module fournit une navigation éditoriale dans le slot `front.header` déjà rendu par les thèmes, sans code propre au module dans un thème. L'éditeur peut associer un lien au slug explicite d'une page publiée ; la publication vérifie ce slug et le front rend alors directement l'ancre canonique `/pages?slug=...`, utilisable après rechargement ou ouverture dans un autre onglet, même hors de la première page de résultats. Les liens vers les autres routes du front et les URL externes gardent leur destination. Un ancien lien ne contenant que `href:'/slug'` reste ambigu : son clic simple résout le slug avant de tenter la route, mais sa copie ou son ouverture dans un autre onglet conserve `/slug` jusqu'à ce qu'un éditeur renseigne le slug de page et republie la navigation. Les métadonnées title, description et canonical du snapshot actif sont appliquées dans le document du navigateur connecté, puis restaurées lorsque la vue perd son droit, sa session ou son activité. Cela ne fournit pas des métadonnées serveur indexables aux visiteurs anonymes.

La promotion `publish` signifie que le snapshot D1 est disponible pour les lecteurs autorisés ; elle ne déploie pas un Site. Le transport HTTP d'opérations rejette actuellement les requêtes anonymes avec `501`, et le service de fichiers n'offre pas de route publique pour ces médias. La publication anonyme, le SEO serveur et l'affichage public de médias demandent des ports hôte explicites. Le module n'ajoute pas ce complément T-06 reporté.

La présentation reprend les préfabriqués `hero`, `features`, `pricing`, `cta` et `footer` ainsi que `landing.css` de `packages/landing/ui` au commit original `6bd6507633b4c17bfc31206d82d1caa9a8af19af`. L'éditeur de sections et le tableau de navigation reprennent les interactions de `landing-admin-client.tsx` et `nav-admin-client.tsx`. Les anciennes routes Hono, SQLite et l'upload base64 ont été remplacés par les opérations D1 et le client R2 du SDK. Le catalogue sidebar de l'ancien module navigation nécessite un port public du catalogue du workspace ; l'édition de ce catalogue n'est pas simulée ici.

L'installation requiert le runtime Worker, D1 partagé, R2 partagé et `creezio.access`. Le module ne crée ni base, ni service, ni processus planifié. Les droits `pages.edit` (admin) et `pages.view` (lecture publiée admin/app) sont attribués par l'administrateur applicatif ; leur présence ne découle pas d'une identité ChatGPT.
