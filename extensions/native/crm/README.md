# CRM natif Creezio

La navigation et la vue CRM sont déclarées pour le workspace et les thèmes front. Les deux interfaces utilisent les mêmes fiches et opérations ; un front headless peut appeler les API natives. La clé d’une modification incertaine est conservée dans le panneau avant son envoi et relue par le statut natif, sans rejouer la commande.

Le workspace CRM permet de gérer entreprises, contacts et prospects. La vue Prospection reprend le kanban original à cinq colonnes, l'ajout nom/ville, le glisser-déposer, les notes et l'archivage. L'API et les outils MCP exposent les mêmes opérations autorisées. Les fiches sont isolées par contexte et partagées entre collaborateurs et audiences explicitement autorisés ; l'audience reste contrôlée sur chaque credential, opération et attribution de `crm.use`. Les modifications vérifient la révision commune de la fiche.

Le module n'installe aucun service externe et ne possède pas de fichiers R2. La recherche native parcourt au plus 500 lignes autorisées par appel ; le curseur permet de continuer. Les lots de lecture D1 et la taille de réponse sont bornés même lorsque les champs texte atteignent leurs maxima. Les références internes contact–entreprise et prospect–contact/entreprise refusent les cibles absentes ou archivées, avec garde au commit. La création ou modification d'un lien incrémente la révision du parent dans le même batch ; un archivage concurrent doit donc échouer sur sa comparaison de révision. Ces écritures déclarent `concurrency:none` car elles comparent plusieurs objets de révisions différentes ; les comparaisons effectives sont fournies dans les plans du module. Les liens vers d'autres modules attendent leurs contrats publics versionnés ; aucun autre module natif actuel n'en fournit pour ces entités. Le candidat T20 raccorde les compositions, verrous, schéma central et vues hôte. Le déploiement et les recettes navigateur/hébergées restent à qualifier.

Les opérations métier API et MCP acceptent aussi un jeton machine, avec une attribution explicite de `crm.use` dans le contexte et l'audience du jeton. La permission reste `default: deny` et une révocation est vérifiée à chaque appel ; ce contrat ne donne aucun accès aux secrets ni aux réglages d'administration.
