# Conversations natives

Le module fournit des conversations Chat et Work, messages, brouillons durables, historique, recherche paginée, archives, événements de progression et pièces jointes privées. Les mêmes opérations servent le workspace et le front avec une session ou un OAuth propre à l’audience. Le SDK `sdk/conversations` conserve l’état du panneau pendant la navigation et relit une mutation incertaine par sa clé sans la rejouer.

Les lignes D1 portent le contexte, le propriétaire et l’audience. Les messages, brouillons, tours, événements et liens de fichiers référencent la conversation par une clé composite. Le port fichiers de l’hôte vérifie D1 et R2 puis fournit un plan de publication dans le même batch que le lien métier. Les opérations ne reçoivent ni clé d’objet R2 ni droit SQL.

Sans fournisseur activé, le détail renvoie `no_provider`. Le panneau lit aussi la configuration publique OpenAI pour distinguer fournisseur manquant, vérification en cours et indisponibilité même sans conversation sélectionnée ; l’envoi exige un modèle confirmé dans la liste autorisée. Aucun texte assistant n’est inventé. Avec OpenAI activé, `turn.start` enregistre le message utilisateur, vide le brouillon, réserve le tour et son outbox dans une seule transaction. Le contrôleur demande ensuite au pont hôte `turn.drive` de progresser ; les lectures restent passives et les événements permettent de reprendre l’affichage.

Les widgets utilisent le SDK public MCP Apps et les opérations des modules. Les messages conservent leurs instances et le pointeur vers le résultat durable autorisé ; les contextes de widgets sont capturés au démarrage du tour. Après mise à jour d’un module, la requête `widget.render.read` relit une exécution historique seulement depuis le message natif, sous les droits actuels, et valide sa sortie contre le schéma du renderer compatible courant. Les instances statiques ne nécessitent pas de résultat d’exécution. Les contextes enregistrés restent liés à la version d’origine et leurs champs sont revalidés avant un nouveau tour. Le panneau conserve les commandes incertaines avant dispatch et les relit sans répétition automatique ; un ancien contrat incertain ne devient pas une nouvelle commande. La qualification T16 navigateur et ChatGPT reste distincte de ces contrats. Les six suites du module se lancent avec `node gate.mjs` ; les recettes local, Sites et fournisseur réel sont documentées séparément.
