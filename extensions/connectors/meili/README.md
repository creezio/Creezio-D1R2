# Meili — connexion et diagnostic des index externes

Cette première tranche connecte Creezio à une instance Meilisearch HTTPS déjà exploitée. Un administrateur saisit son origine et sa clé API dans le workspace. La clé est scellée dans le coffre natif, n’est jamais retournée ni stockée dans le panneau et n’est utilisée que par le port serveur déclaré. Aucun serveur Meili n’est installé ou maintenu par Creezio.

`config.read`, `config.set`, `config.key.set` et `config.key.revoke` sont des opérations administratives à révision CAS et clé de demande. Changer d’origine avec une clé encore scellée est refusé, même si la connexion a été désactivée : il faut révoquer la clé, changer l’origine puis enregistrer une nouvelle clé. `connection.check` est une lecture administrative distincte, accessible à un compte machine muni de `creezio.meili:read`. Elle fait au plus un GET déclaré `/indexes?limit=1` avec Bearer, puis ne retourne que `authenticated` et `status`. Une erreur d’authentification distante donne `key_rejected` ; aucun nom, total, document ou corps fournisseur ne sort de cette opération.

`index.list` est une lecture **réservée à `creezio.meili:manage`**, dans le contexte actif. Elle appelle une page GET `/indexes?offset=…&limit=…` (20 entrées maximum), retourne les UID, clés primaires, dates et le total effectivement fournis par Meilisearch, avec un curseur de page suivant. Aucune réponse fournisseur brute, document ou clé API ne sort. Une configuration changée ou révoquée pendant la requête invalide la lecture. La carte administrative originale affiche ce diagnostic sur demande, sans précharger d’index ni démarrer de recherche. Aucun widget de résultats n’est déclaré, car aucun document de recherche n’est servi.

Le [GET de liste d’index Meilisearch](https://www.meilisearch.com/docs/reference/api/indexes/list-all-indexes) a été vérifié une fois avec un accès externe autorisé (HTTP 200, enveloppe JSON conforme, 181 octets ; reçu expurgé `CREEZIO-T28-MEILI-EXTERNAL-READONLY-2026-09-29.json`). Ce témoin historique ne qualifie pas la nouvelle pagination ni l’interface 0.2.0 chez le fournisseur. Aucun index métier, aucune indexation, aucune recherche Meili et aucune interface de recherche globale ne sont livrés par cette tranche.

La recherche Catalogue `product.search` existante continue sans Meili. La recherche globale native T05 est reportée par l’utilisateur ; son raccord demandera une explication et un accord propres. REQ-2801 reste ouverte pour les écritures asynchrones, reconstruction, suppression, filtres contextuels, recherche et recette complète. Aucun POST fournisseur, daemon, scheduler ou service tiers embarqué n’est introduit ici.
