# Connecteur Resend — candidat T29

Ce module configure un transport Resend pour la messagerie native. L’administrateur choisit une adresse expéditeur, scelle une clé API dans le coffre serveur, active ou révoque la configuration, puis peut lire les seuls noms et états de domaines retournés par Resend. L’origine est fixée à `https://api.resend.com` ; l’UI, l’API et MCP ne reçoivent jamais la clé. Les configurations sont isolées par contexte et soumises à la permission admin `resend.manage`. La query publique `delivery.readiness` exige séparément `resend.use` en admin ou app et ne rend que `state/from/configRevision` ; `ready` signifie configuration locale éligible, pas délivrabilité prouvée. L’hôte revalide config, coffre et droits avant chaque effet.

Le descripteur hôte déclare `GET /domains`, `GET /emails/receiving/{id}` et `POST /emails` avec chemins, champs, tailles et en-tête d’idempotence fixes. Il déclare aussi `binaryDownloads[email.received.attachment]` : GET de métadonnées `/emails/receiving/{parentId}/attachments/{childId}` puis CDN signé sur `https://inbound-cdn.resend.com/{parentId}/attachments/{childId}`. L'hôte seul réalise ces deux GET sous contrôle d'un événement signé, de la connexion active et de 10 Mio d'octets ; le handler n'obtient ni URL ni clé. Le port mutateur commun dérive sa clé de l’exécution canonique. **Aucune opération publique d’envoi n’existe dans ce module** : l’envoi part d’une intention durable Messagerie, puis l’hôte transmet le snapshot immuable et ses fichiers privés. Aucun fetch privé, secret en module, moteur d’outbox ni polling ne sont ajoutés.

Le corps métier sérialisé reste borné ; le port hôte ajoute jusqu’à 50 fichiers R2 et 10 Mio cumulés dans le POST déclaré, sans base64 en D1/outbox. Le succès HTTP signifie acceptation fournisseur et ne prouve pas livraison. Le callback Resend est vérifié sur les octets bruts puis conserve seulement des métadonnées signées sous une permission distincte. Messagerie rapproche explicitement les accusés d’un envoi connu. Pour l’entrant, la lecture fournisseur exige d’abord un événement `email.received` de la connexion active ; elle expose seulement les métadonnées bornées des pièces jointes. Messagerie stage chaque ID vers R2 privé puis importe la liste exacte dans un commit D1 avec le message. Aucun appel Resend réel n’a été exécuté.
