# Connecteur Resend — candidat T29

Ce module configure un transport Resend pour la messagerie native. L’administrateur choisit une adresse expéditeur, scelle une clé API dans le coffre serveur, active ou révoque la configuration, puis peut lire les seuls noms et états de domaines retournés par Resend. L’origine est fixée à `https://api.resend.com` ; l’UI, l’API et MCP ne reçoivent jamais la clé. Les configurations sont isolées par contexte et soumises à la permission admin `resend.manage`. La query publique `delivery.readiness` exige séparément `resend.use` en admin ou app et ne rend que `state/from/configRevision` ; `ready` signifie configuration locale éligible, pas délivrabilité prouvée. L’hôte revalide config, coffre et droits avant chaque effet.

Le descripteur hôte déclare `GET /domains` et `POST /emails` avec champs, tailles et en-tête d’idempotence fixes. Le port mutateur commun dérive sa clé de l’exécution canonique. **Aucune opération publique d’envoi n’existe dans ce module candidat** : l’envoi doit partir d’une intention durable créée dans Messagerie, puis être dispatché par l’hôte depuis un snapshot immuable et rapproché par une opération canonique séparée. Aucun fetch privé, secret en module, moteur d’outbox ni polling ne sont ajoutés.

La première limite du mutateur est 65 536 octets de corps HTTP. Les pièces jointes privées R2 ne sont donc pas incluses dans ce descriptor. Le raccord initial devra refuser sans effet tout message avec pièces jointes ou contenu hors budget ; un port hôte de transmission bornée et déclarée reste à développer pour les pièces, sans URL publique permanente. Le succès HTTP signifie acceptation fournisseur et ne prouve pas livraison. Les accusés signés et la réception attendent le raccord webhook hôte et la projection Messagerie. Aucun envoi réel n’a été exécuté.
