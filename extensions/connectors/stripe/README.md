# Stripe — première tranche de facturation projetée

Ce module optionnel réemploie la page « Facturation / Abonnements » de l'application Creezio originale. Un administrateur disposant de `stripe.manage` saisit une clé API Stripe, l'envoie à la commande de configuration qui la scelle dans le coffre natif du contexte, active la connexion et déclenche explicitement la lecture d'une collection. Le descripteur fixe `https://api.stripe.com`, l'en-tête `Stripe-Version: 2026-08-26.dahlia` et trois GET : clients, abonnements (`status=all`) et factures. La clé n'est ni renvoyée dans les sorties ni conservée dans l'état du panneau ou le journal de commandes. Le mode test est privilégié pour la recette ; une clé live autorisée n'est pas interdite par le contrat.

`sync.start` ouvre un run local sous révision CAS. Chaque `sync.page` lit au plus huit objets, projette leurs champs nécessaires et avance le curseur avec ces écritures dans un seul commit D1. La pagination reste explicite et bornée. L'état `partial` indique une reprise nécessaire ; `pages_exhausted` signifie seulement que la dernière page de ce parcours a été atteinte. Un résultat incertain se relit avec la même `requestKey`, jamais par un second envoi automatique. Chaque remplacement ou révocation de clé change la génération de connexion : les anciens curseurs sont refusés et les projections antérieures deviennent invisibles, sans effacement de données. Les opérations de lecture `sync.state`, `customer.list`, `subscription.list` et `invoice.list` servent la page, l'API, MCP et un widget d'état. Les droits `stripe.read` et `stripe.manage` sont explicites, administratifs, contextuels et refusés par défaut.

Les montants de facture sont les entiers bruts Stripe en unités mineures avec devise. L'écran ne calcule pas de MRR, d'abonnements actifs globaux ou de factures impayées globales à partir d'une page incomplète. Il conserve les cartes et tableaux d'origine, mais marque ces agrégats et les événements webhook indisponibles. Les noms de clients projetés servent seulement à la liste administrative ; adresses, cartes, métadonnées et réponse Stripe brute sont exclues.

Cette tranche ne fournit ni Checkout, ni mutation Stripe, ni réception webhook, ni paiement, ni rapprochement de flotte, ni front client. Elle ne clôt pas REQ-2701. La première recette fournisseur doit encore utiliser une clé Stripe de test et vérifier les lectures réelles ; les six suites et l'intégration D1 avec transport simulé ne la remplacent pas. SDK `^1.4.0` est candidat, pas encore public. Les modules n8n et le SDK déjà publié conservent leurs contrats.
