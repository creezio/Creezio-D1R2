# Docker local persistant — T-31

Tranche en construction sur `core/t08-publication-foundations`, liée à [T-31](TODO.md#T-31) et [REQ-3101](EXIGENCES.md#REQ-3101). Docker utilise les mêmes scripts locaux, le même Worker et les mêmes modèles que le démarrage direct ; il ne constitue pas une architecture applicative distincte ni une certification de production Miniflare.

L'adaptateur conserve D1, R2 et le verrou local dans un volume `.wrangler` partagé. Le conteneur s'exécute avec le compte `node` et n'expose son port qu'en loopback. Il n'embarque ni n8n, ni Meili, ni un serveur par utilisateur. Les dépendances et le cache de build sont réutilisés ; secrets, données locales et répertoires de contrôle sont exclus du contexte de l'image.

La [recette Docker](../adapters/docker/QUALIFICATION-T31.md) a vérifié le 27 septembre l'installation native, la connexion HTTP, l'exclusion concurrente, les écritures D1/R2, l'arrêt, le redémarrage, la recréation et la restauration d'un volume distinct. Elle utilise uniquement des données synthétiques. L'image `sha256:ba5a692fe1534585caaac9a40f7d74a2fb638c96f71f8a770c5dbb3073d4a39b` conserve le runtime de la base `56eb0159` ; elle ne qualifie pas le registre écrit en parallèle. Les preuves hors source donnent versions Docker, empreintes des sources, objet R2 et archive, réponses HTTP et nettoyage. R2 a été contrôlé par son binding persistant ; sa future route HTTP reste à qualifier. Aucun conteneur de test ne reste actif. Le Docker de développement ne requiert aucun token du registre central ; une publication Cloudflare ultérieure utilisera le contrôle T-08.
