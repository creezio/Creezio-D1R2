# Docker local persistant — T-31

Tranche en construction sur `core/t08-publication-foundations`, liée à [T-31](TODO.md#T-31) et [REQ-3101](EXIGENCES.md#REQ-3101). Docker utilise les mêmes scripts locaux, le même Worker et les mêmes modèles que le démarrage direct ; il ne constitue pas une architecture applicative distincte ni une certification de production Miniflare.

L'adaptateur conserve D1, R2 et le verrou local dans un volume `.wrangler` partagé. Le conteneur s'exécute avec le compte `node` et n'expose son port qu'en loopback. Il n'embarque ni n8n, ni Meili, ni un serveur par utilisateur. Les dépendances et le cache de build sont réutilisés ; secrets, données locales et répertoires de contrôle sont exclus du contexte de l'image.

La [recette Docker](../adapters/docker/QUALIFICATION-T31.md) a vérifié le 27 septembre l'installation native, la connexion HTTP, l'exclusion concurrente, les écritures D1/R2, l'arrêt, le redémarrage, la recréation et la restauration d'un volume distinct. Elle utilise uniquement des données synthétiques. L'image `sha256:ba5a692fe1534585caaac9a40f7d74a2fb638c96f71f8a770c5dbb3073d4a39b` conserve le runtime de la base `56eb0159` ; elle ne qualifie pas le registre écrit en parallèle. Les preuves hors source donnent versions Docker, empreintes des sources, objet R2 et archive, réponses HTTP et nettoyage. R2 a été contrôlé par son binding persistant ; sa future route HTTP reste à qualifier. Aucun conteneur de test ne reste actif. Le Docker de développement ne requiert aucun token du registre central ; la publication Cloudflare T32 utilise le contrôle T-08.

La recette Linux T32 suivante a exercé ce Docker avec l'application originale et des données réelles de qualification : compte administrateur, conversation, brouillon et fichier R2 présents après remplacement de l'image, transfert puis première mise à jour vers Cloudflare et arrêts propres du conteneur (code zéro). Les reçus `CREEZIO-T32-LINUX-CF-PRESERVATION-2026-09-28.json`, `CREEZIO-T32-LINUX-STOP-AFTER-TRANSFER-2026-09-28.log` et `CREEZIO-T32-LINUX-STOP-AFTER-UPDATE-2026-09-28.log` documentent ce parcours ; [la réalisation T32](IMPLEMENTATION-T32.md) borne les preuves de publication et d'update.
