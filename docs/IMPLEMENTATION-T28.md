# T28 — Connexion et diagnostic d'une instance Meili externe

## Candidat source 0.3.0, 30 septembre 2026

Le code en cours de composition ajoute une projection Catalogue facultative déclarée dans `contracts.search`, liée au port public `meili.index@1.0.0`. Le port hôte lit seulement le modèle produit et le droit `catalog.view` du contexte courant. Les brouillons et archives deviennent des suppressions. La génération a un UID déterministe propre au contexte ; ses pages de 50 lignes produisent des lots durables d’au plus 13 écritures. Une émission POST retourne une tâche 202, puis une lecture GET de cette tâche doit confirmer le bon index, type et succès avant l’avancement du curseur. Une issue inconnue bloque la réémission ; un abandon explicite conserve l’ancienne génération active et met l’autre en quarantaine.

`index.search` relit les ID trouvés sur le modèle propriétaire et revérifie son droit. Les totaux/facettes bruts du fournisseur sont ignorés ; les compteurs renvoyés portent uniquement sur la page visible. Le widget MCP Apps `search-results` affiche ces mêmes hits et relance une lecture directe sur la même source. L’interface admin expose les étapes de progression. Les six suites du module et l'intégration D1 Miniflare du candidat passent localement avec un fournisseur simulé : lecture Catalogue par le port déclaré, émission, confirmation de tâche, suppression, issue inconnue et recherche relue sous les droits du propriétaire. La composition et les archives exactes sur le SDK 1.6 final, la CI du candidat et les POST/tâches/recherches sur fournisseur réel restent à qualifier. Les passages ci-dessous conservent l’état et les reçus des tranches antérieures ; ils ne constituent pas une recette fournisseur de 0.3.0.

La première émission réelle a créé la tâche Meili 165. Sa lecture seule indique `failed`, `index_primary_key_multiple_candidates_found`, deux documents reçus et zéro indexé (`outputs/CREEZIO-T28-MEILI-TASK165-READONLY-2026-09-30.json`). Le POST `/indexes/{id}/documents` déclare maintenant le paramètre fixe `primaryKey=id` ; le port hôte l’applique aussi aux mutations. Un test local vérifie l’URL et le corps de deux documents avec plusieurs champs en `id`. Cette correction ne transforme pas la tâche 165 en succès et demande une nouvelle recette fournisseur sur une émission distincte.

## Historique des tranches 0.1.0 et 0.2.0

Ces tranches du module optionnel fournissaient une **connexion** puis un diagnostic de liste d'index, sans recherche Meili. Creezio ne fournit, n'installe et ne maintient aucun service Meili. L'application reste utilisable sans lui ; la recherche déjà livrée par le Catalogue continue d'utiliser ses propres opérations. La recherche globale native T05 est reportée et demande une explication puis un accord distinct avant son raccord.

Le module `creezio.meili` reprend la carte de réglages de recherche de l'interface originale. Un administrateur autorisé configure une origine HTTPS et une clé API dans le contexte courant. La configuration D1 est versionnée ; la clé est scellée dans le coffre natif et n'est ni renvoyée par les opérations ni conservée dans le panneau. Les commandes de réglage ont une clé de demande et une révision attendue. Changer l'origine exige d'abord la révocation de la clé existante, même si la connexion est désactivée ; l'administrateur fournit ensuite une nouvelle clé pour la nouvelle origine. Révocation, changement de session, d'audience ou de contexte empêchent de réutiliser un ancien état de vue.

La première lecture distante `connection.check` déclare `GET /indexes?limit=1` avec authentification Bearer et borne la réponse JSON. Elle retourne seulement la confirmation d'accès, sans nom d'index, document, total ou corps fournisseur. Elle ne prouve aucune indexation métier. La tranche 0.2.0 ajoute `index.list` : une page GET `/indexes` de 20 entrées au maximum, avec offset et limite bornés, ne projetant que UID, clé primaire, dates, total fournisseur et curseur. Elle exige `creezio.meili:manage` en audience admin ; `meili.read` seul est refusé. Le module relit la configuration après le GET pour refuser une réponse obtenue pendant une rotation ou une révocation. La carte de réglages d'origine affiche ce diagnostic sur demande, sans recherche de documents, widget ni nouveau raccourci. Aucune URL, méthode ou requête arbitraire n'est fournie au handler.

Un GET direct unique vers une instance Meili autorisée a répondu HTTP 200 avec une enveloppe conforme ; le reçu expurgé `CREEZIO-T28-MEILI-EXTERNAL-READONLY-2026-09-29.json` ne contient aucun identifiant d'index ni secret. La PR #53 a passé 1 247/1 247 contrôles. Sur Linux, la recette du code `3b2131c` a adopté les deux seules tables Meili, confirmé quatre intentions de configuration et affiché « Connexion Meilisearch vérifiée » dans l'interface après un contrôle réel. Le premier résumé du helper PowerShell était ambigu malgré une exécution HTTP réussie ; la confirmation UI et le reçu expurgé `CREEZIO-T28-LINUX-RECIPE-3B2131C-2026-09-29.json` bornent cette preuve. Aucun index, tâche distante, document ou service Meili n'a été créé par cette recette. La lecture paginée 0.2.0 passe ses six suites locales et une intégration D1/coffre/API/MCP simulée ; elle est intégrée par PR #76 et livrée dans Core `cd2eeb2`. Sur Linux, une lecture avec le fournisseur réel a confirmé `index.list`, une page d'une métadonnée d'index, sous l'audience admin `manage`, puis la déconnexion (`CREEZIO-T28-MEILI-INDEX-READ-20260930T120126055Z-4ed98848.json`). La même source est publiée sur Cloudflare sans recette Meili fournisseur sur ce Worker ; aucune lecture de document, indexation ou recherche native n'est déduite de la liste.

À l'issue de 0.2.0, REQ-2801 restait ouverte : l'indexation incrémentale, les suppressions, la reconstruction reprenable et les tâches Meili n'étaient pas encore implémentées. Les déclarations de recherche n'avaient alors aucun consommateur runtime et le bouton « Réindexer » était indisponible. Le candidat 0.3.0 décrit plus haut ajoute ces chemins et relit les résultats sur le propriétaire ; ses preuves D1 locales n'établissent toujours pas leur effet sur Meili réel. La recette de recherche/indexation native et les profils hébergés restent nécessaires avant de clore T28.
