# T28 — Connexion à une instance Meili externe

Cette première tranche ajoute un module optionnel de **connexion**, pas un moteur de recherche. Creezio ne fournit, n'installe et ne maintient aucun service Meili. L'application reste utilisable sans lui ; la recherche déjà livrée par le Catalogue continue d'utiliser ses propres opérations. La recherche globale native T05 est reportée et demande une explication puis un accord distinct avant son raccord.

Le module `creezio.meili` reprend la carte de réglages de recherche de l'interface originale. Un administrateur autorisé configure une origine HTTPS et une clé API dans le contexte courant. La configuration D1 est versionnée ; la clé est scellée dans le coffre natif et n'est ni renvoyée par les opérations ni conservée dans le panneau. Les commandes de réglage ont une clé de demande et une révision attendue. Changer l'origine exige d'abord la révocation de la clé existante, même si la connexion est désactivée ; l'administrateur fournit ensuite une nouvelle clé pour la nouvelle origine. Révocation, changement de session, d'audience ou de contexte empêchent de réutiliser un ancien état de vue.

La seule lecture distante de cette tranche est `connection.check` : le port de connecteur déclare `GET /indexes?limit=1` avec authentification Bearer et borne la réponse JSON. Après validation, il retourne seulement la confirmation d'accès, sans nom d'index, document, total ou corps fournisseur. Cette route peut confirmer qu'une clé lit la liste des index, même vide ; elle ne prouve aucune indexation métier. Les droits de réglage restent administratifs ; un compte machine ne peut lire l'état de connexion que sous sa portée explicite. Aucune URL, méthode ou requête arbitraire n'est fournie au handler.

Un GET direct unique vers une instance Meili autorisée a répondu HTTP 200 avec une enveloppe conforme ; le reçu expurgé `CREEZIO-T28-MEILI-EXTERNAL-READONLY-2026-09-29.json` ne contient aucun identifiant d'index ni secret. Il qualifie l'accès fournisseur, sans qualifier à lui seul l'API, le MCP, l'interface ou l'archive du module. Les suites de contrat et la recette du module doivent être rapportées séparément sur leur source exacte. Aucun index, tâche distante, document ou service Meili n'a été créé par cette vérification.

REQ-2801 reste ouverte. L'indexation incrémentale, les suppressions, une reconstruction reprenable par génération et les tâches asynchrones Meili requièrent une tranche d'écriture durable ; un HTTP 202 ne suffit pas à confirmer leur effet. Recherche, facettes et compteurs demanderont des filtres de contexte appliqués avant agrégation et une réautorisation des résultats. Les déclarations de recherche présentes dans les contrats n'ont pas encore ce consommateur runtime ; ce module ne les active pas fictivement. Le bouton « Réindexer » reste indisponible avec une explication dans l'interface. La recette avec Meili réel et recherche native, ainsi que les profils hébergés, restent à réaliser avant de clore T28.
