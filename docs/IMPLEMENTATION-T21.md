# T21 — Pages et navigation

`creezio.pages-navigation` reprend les éditeurs, composants de landing et cinq familles de sections du Creezio original. Les quatre modèles D1 décrivent brouillons, snapshots publiés, réglages et navigation. Les opérations déclarées partagent validation, permissions, révisions et idempotence entre workspace, API et MCP ; le front thémé compose automatiquement sa contribution.

Publier produit un snapshot distinct du brouillon. Modifier le brouillon ne change pas silencieusement la version publiée. Les médias restent des objets privés R2 référencés par leur preuve native. Les liens et le contenu des sections sont validés et bornés ; les conflits de révision empêchent d'écraser une modification concurrente. Le journal SDK et les états de panneau conservent les commandes incertaines et les saisies entre onglets, y compris un JSON temporairement invalide pendant son édition.

Les suites du module passent 22 contrôles ; les widgets sont explicitement non applicables. L'intégration D1 réelle vérifie brouillons, snapshots et frontières d'accès. Sur le profil Linux à 13 modules du candidat `589a827`, le navigateur a enregistré deux révisions de brouillon, publié la révision 1, puis repris un brouillon en révision 4. Il a sauvegardé et publié la navigation éditoriale ; le front authentifié `/pages` a affiché la section hero et le lien. Cette preuve concerne le code UI `589a827`, pas une publication hébergée.

La tranche suivante compose la navigation éditoriale dans `front.header` via les slots déjà acceptés par les deux thèmes, sans branche dédiée dans un thème. Une lecture `page.published.resolve` utilise l'égalité sur le slug publié dans le contexte courant ; le port D1 interdit de trier par ce champ nullable, donc la lecture ne fournit aucun `order.indexId`. Un lien portant `pageSlug` est vérifié lors de la publication de la navigation et rendu avec l'ancre canonique `/pages?slug=...` dès l'affichage. Les anciens liens `href:'/slug'` ne peuvent être automatiquement distingués des routes d'un autre module : leur clic simple conserve la résolution dynamique, tandis que copie et nouvel onglet gardent `/slug` jusqu'à une édition explicite et une nouvelle publication. La route canonique garde la sélection après rechargement, même hors des 50 premiers résultats. La vue active pose temporairement title, description et canonical à partir du snapshot publié puis restaure les valeurs précédentes lorsqu'elle se désactive. Ces changements sont validés par les suites du module et une intégration D1 ciblée ; aucune nouvelle recette navigateur ou Site n'est revendiquée à ce stade.

La lecture du front requiert toujours une identité native. Publication anonyme, distribution publique des médias et SEO serveur indexable restent à réaliser via des ports hôte explicites. Aucun média n'a été téléversé dans cette recette. Les outils MCP existent sans renderer de widget propre ; cette absence est déclarée et testée, sans prétendre avoir qualifié une UI ChatGPT. La frontière hôte encore requise est détaillée dans `outputs/CREEZIO-T21-PUBLIC-LANDING-GAP-2026-09-28.md`.
